# Fluency evaluation

Fluency evaluation measures how well a *base* (pretrained, not instruction-tuned)
model continues a short sentence prefix, judged pairwise by an LLM judge.

## Dataset

Contexts (sentence prefixes to complete) come from
[`geoalgo/multilingual-fluency`](https://huggingface.co/datasets/geoalgo/multilingual-fluency),
43 languages with 200 prefixes each (`general sentences`, `history`, `economics`,
`math`, `programming`). It is generated by `generate_fluency.py` in this
directory and superseded the older, 6-language
[`geoalgo/multilingual-contexts-to-be-completed`](https://huggingface.co/datasets/geoalgo/multilingual-contexts-to-be-completed).

To evaluate fluency, run:
```
judgearena \
  --task fluency-french \
  --model.name "LlamaCpp/./models/gemma3-1b-pt.gguf" \
  --model.baseline "LlamaCpp/./models/smollm3-3b-base.gguf" \
  --judge.model "OpenRouter/google/gemma-4-31b-it" \
  --generation.n_instructions 1 --model.max_out_tokens 512 --judge.max_out_tokens 512
```

Where `{lang}` can be any of:

```
english, mandarin-chinese, hindi, spanish, french, standard-arabic, bengali,
russian, portuguese, indonesian, japanese, german, turkish, italian,
ukrainian, polish, romanian, dutch, greek, hungarian, czech, catalan,
bulgarian, swedish, danish, finnish, slovak, norwegian, croatian, georgian,
lithuanian, slovene, latvian, albanian, macedonian, estonian, basque,
galician, bosnian, serbian, icelandic, maltese, irish
```

The list of available languages is available at `judgearena/datasets/fluency.py`.

## Validation against human annotations

The LLM judge used for fluency (`judgearena.prompts.registry`'s `"fluency"`
prompt preset) is validated against **human fluency annotations in
Norwegian**.

We use [`ltg/normistral-fluency-annotation`](https://huggingface.co/datasets/ltg/normistral-fluency-annotation) dataset
with 907 pairwise comparisons (5 annotators) where a human picked which of two
model completions was more fluent, or called it a tie, see more details in the [paper](https://arxiv.org/pdf/2512.08777)
which introduced this dataset. As in the original paper, we exclude ties.

On this dataset, we have an judge-human accuracy of **81.4%** while the average human-human annotator accuracy is 93.4%.

Here are inter-annotators agreement (human vs human, excluding ties):
```
annotator_A: 78/84 = 0.929
annotator_B: 164/173 = 0.948
annotator_C: 58/62 = 0.935
annotator_D: 146/154 = 0.948
annotator_E: 70/77 = 0.909
Average annotator accuracy: 0.934
```

and LLM / Human agreement (excluding ties):
```
annotator_A: 78/91 = 0.857
annotator_B: 187/229 = 0.817
annotator_C: 46/59 = 0.780
annotator_D: 147/175 = 0.840
annotator_E: 56/72 = 0.778
Average LLM accuracy: 0.814
```

Rerun with:

```bash
python scripts/eval_fluency_norwegian/eval_fluency.py --judge_model OpenRouter/google/gemma-4-31b-it
```

The script judges each unique `(prompt, response_a, response_b)` pair once in
each order (bias-corrected via `--both`, on by default) using judgearena's own
`"fluency"` prompt preset — no standalone/duplicated prompt logic — and
compares the resulting label (`A` / `B` / `tie`) against each human choice.
